# Categories to check

The **Fixable via --fix** column says whether this category has a concrete file/state change `--fix` can offer to apply, or is advisory-only (describes past session behavior with nothing in the current repo to edit).

| Category | What to look for in the scan data | Fixable via --fix |
|---|---|---|
| **Context pollution** | One session's `turns` cover unrelated topics (e.g. debugging a backend issue, then asking about CSS, then reviewing a PDF) — each unrelated pivot inflates context all subsequent turns pay for. Flag sessions that should have been split. | Advisory-only — describes past session shape, nothing to edit now. |
| **Duplicated work** | Near-identical prompts recurring across sessions/turns (same question re-asked, same file re-explained) — signals missing memory or a stale mental model the user has to keep re-supplying. | Advisory-only, unless the cause is a missed memory — see that row. |
| **LLM used where a script would do** | Turns asking Claude to parse/reformat/compute/summarize structured data (logs, CSV, JSON, diffs) that a one-off script or existing CLI tool could produce deterministically and cheaper. Look for prompts like "count/list/extract/convert X from Y". | Advisory-only — the better approach only applies to the *next* similar task, there's no past turn to rewrite. |
| **MCP servers connected but unused** | `mcpToolUsage` gives `{ available, used }` per MCP server. A server with many `available` tools and `used: 0` across sessions costs tokens every turn for nothing (at least a listing line per tool, the full schema when tools aren't deferred). Also flag tools in `mcpToolCalls` that appear only very late in a long session. Caveat: older transcripts lack the tool-listing attachments, so `available` counts only called tools there. Use `mcpServers` for the human-readable server names. | Advisory-only — recommend disconnecting or scoping the server; `--fix` does not edit MCP config. |
| **Always-on listing overhead** | `skillListing` (`count`, `chars`) is the skill catalog injected into every session; tens of thousands of chars, or 100+ skills, is a fixed per-session cost that grows with every installed plugin. Pair it with `mcpToolUsage` totals for the full picture of what loads before the user types anything. | Advisory-only — recommend uninstalling or project-scoping rarely used skills/plugins. |
| **Skills without progressive disclosure** | Skill files that are long/monolithic (no separate reference files) get fully loaded on every invocation. `skillLoads` shows each injected skill body and its size (chars), and `skillInvocations` shows whether it was a slash command or a model `Skill` call — a large body loaded repeatedly is the strongest signal. Rule of thumb: keep the always-loaded `SKILL.md` under ~500 words, moving heavy reference material (tables, templates, exhaustive examples) into separate files pulled in on demand. If the `superpowers:writing-skills` skill is installed, it has the fuller rationale — consult it for extra detail, but the rule above is sufficient on its own. | **Fixable** — split per `references/split-guide.md`. |
| **Oversized or over-specified prompts** | User turns that are very long (`length` in scan data — `turns` holds only human-typed text; injected skill bodies are in `skillLoads`, not here) with excessive upfront detail the agent didn't need immediately — vs. a short prompt plus follow-up clarification, which is often cheaper because unused detail isn't loaded speculatively. | Advisory-only — describes past turns, nothing to edit now. |
| **Verbose/unsplit harness files** | CLAUDE.md, AGENTS.md, or the project's memory (`~/.claude/projects/<encoded>/memory/MEMORY.md`) that mixes always-relevant rules with rarely-needed detail (long troubleshooting runbooks, one-off project history) in a single file loaded every session — should be split with the rare parts referenced, not inlined. | **Fixable** — split per `references/split-guide.md`. |
| **Wrong model for the task** | Each turn in `turns` carries the `model` that answered it; `tokensByModel` shows where spend went. Flag mechanical/repetitive turns (rename, reformat, run tests, look something up) answered by a high-capability model, or hard design/debugging turns answered by a small one. | Advisory-only — a future-session setting, not a file to edit. |
| **Subagent delegation** | `subagents` lists each subagent with `agentType`, requested `model`, `promptLength` (the brief), `tokens`, `toolCalls` and `readTargets`; `subagentTokens` is their total, so compare it to the main thread's `tokens`. Flag high-capability subagents doing mechanical work, very long briefs that restate context the subagent could have read, subagents that re-read files the parent already read (`readTargets` overlap), and many subagents spawned where one would do. | Advisory-only — describes past delegation. |
| **Missed memory opportunities** | The user restates the same preference, correction, or project fact in multiple sessions — each restatement is tokens that a saved memory would have avoided. | **Fixable** — save as a memory entry now. |
| **Redundant large reads/fetches** | `readTargets` entries with a count above 1 in one session, or the same target recurring across sessions — the same file or URL read repeatedly instead of cached/summarized once. | Advisory-only — describes past turns, nothing to edit now. |
